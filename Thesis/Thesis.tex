	\section{Mission Profile} \label{se:mission_profile}
		% mission profile general
		A model of the mission profile was created to describe a potential mission with continuous position, velocity, and acceleration with respect to time. The mission profile is modeled as a series of mission profile segments. Constraints are put on the position, velocity, and acceleration at the nodes between mission profile segments. The remaining values at the nodes are calculated using basic kinematic equations. At values of time between mission segment nodes, the position, velocity, and acceleration are interpolated using cubic Hermite splines. [citation needed] Acceleration changes linearly with respect to time. 
		
		% The mission profile 
		The mission profile is based on a potential mission during the 2025 Palisades wildfire. The distance for the mission profile is estimated to be 5600m, the distance from the north edge of the active fire area to south edge of the wildfire. Using elevation maps of the surrounding area, the height required to transverse this mission path is 460m. [cite map] Timesteps were set so that maximum x-velocity to be under 12m/s. 
	
		The climb, cruise, and descent periods are each described using two separate cubic Hermite spline intervals to prevent over-defining the mission profile. Figure \ref{fig:xvy} shows the altitude for the mission profile against the down range position. Figure \ref{fig:yvt} shows the altitude over time. Figure \ref{fig:xvt} shows the downrange position with respect to time. Table \ref{tab:profcons} shows the constraints on the mission profile. The duration shows the time between spline intervals. Blank entries are where no constraint was applied.

	\subsection{Thrust Calculation}\label{ss:thrust}
		
		A calculation of the thrust profile is required in order to preform the power and fatigue analysis. 
		
		The thrust equation over the duration of the mission profile is shown below. Both the acceleration and drag forces are considered.  		
		
		$$ F_\text{thrust}(t)= +-v(t)^2 * s_a * \rho * c_d + (a(t) + g) * m $$ \label{eq:thrust}
		
		The v(t) and a(t) represent the velocity and acceleration of the mission profile at given point in time. 
		
		$s_a$ is an estimate of the surface area of UAV. This is obtained by summing the projected surface of every beam and hub segment with the projected surface area of the two batteries. It is a function of thee design variables.
		
		$\rho = 1.2250\unit{\kilogram\per\meter\cubed}$ is the air density. $c_d = 0.256$ is the drag coefficient. [How to justify?] $g = 9.8066\unit{\meter\second\squared}$ was used for the gravity constant. 
		
		The mass is estimated as the sum of 45kg payload, the mass of the frame, and the mass of the two batteries.
		
		To simulate the pre-liftoff, and post-landing period, a rev up and rev down period were added to the thrust forcing function. This was modeled as a linear increasing force with respect to time up until the force required for take off for the rev up period. The rev down period was modeled as a linearly decreasing force until no force is applied. A duration of 5 seconds was selected for both periods.

		\subsection{Energy Consumption Calculation} \label{ss:energy_consumption_calc}
		
		The energy consumed over the entire mission duration was taken by subtracting the integral of the power draw with respect to time from the batteries overall energy capacity. Equation \ref{eq:p_to_e} describes the relationship between the energy remaining in the battery and the power consumed. $E_{Remaining}(t)$ is the total energy remaining between both batteries as a function of time. $E_{Capacity}$ is the energy stored by a fully charged battery. $t$ is the time since the start of the mission.  
		
		
		$$  E_{Remaining}(t) = E_{Capacity} - \int_{0}^{t} P(t)  $$ \label{eq:p_to_e} 
		
		
		The integral of the power is calculated using scipy.integrate.cumulative{\_}trapezoid to find the energy consumed. The number of timesteps was set to a finite number and is a varibale set when running the optimization function.

		\section{Solvers} \label{se:solvers}
			
		A FEA model was created with three separate solvers. 
		
		The static solver, which is used to calculate the response given a static loading, the dynamic solver, which calculate the response given a force of an oscillating force at a given frequency, and the transient solver which calculates the response given a time-changing force. 
		
		\subsection{Static} \label{ss:static}
			
			
			The static solver calculates the reactions, displacements, and rotations given a specific set of point loads and moments in static equilibrium. The static solve uses the partitioned stiffness matrix, known static forces and moments, known static displacements to solve for the unknown reaction forces, moments, displacements, and rotations. The scipy.linalg.solve function is used to solve for unknown displacements. The displacements, rotations, forces,and moments are used to calculate shape functions and stresses for each beam in the state of static stress is calculated using the formulation discussed in section \ref{ss:seg_model}.
			
			
			The static solver is the solve\_static method within the BeamSystem class. The method solves the global and local displacements of each beam. The local displacements for each BeamElement object within the BeamSystem object are solved by running the solve\_local method within each Beam object. This method applies the transformation matrix to the results. The solve\_shape\_functions method and find\_stresses methods are used to find the state of stress at stable equilibrium within each beam. 
					
			
		\subsection{Dynamic} \label{ss:dynamic}
			
			The dynamic solver solves the amplitude of reactions, displacements, and rotations give a set of oscillating loads and moments.  The boundary conditions are static. Each force and moment applied is assumed to have the same frequency and phase for the given solver. The dynamic stiffness matrix is calculated from the stiffness and mass matrices using the formula $[K_d] = [K] - \omega^2 * [M]$. Damping is assumed to be 0. $[K_d]$ is the dynamic stiffness matrix.  $[K]$ is the static stiffness matrix and $[M]$ is the mass matrix. $\omega$ is the frequency of the loads and moments. The scipy.linalg.solve function is used to solve for unknown displacement amplitudes. Three amplitudes are stored for each direction in three-dimensional space. The oscillating stress amplitude is calculated for each element by substituting the assumed displacements in the stress solver and instead solving for the stress for the stress amplitude. [make this more precise]
			
			% self.kuu - (ang_vel ** 2) * self.muu - ang_vel * (self.muu * alpha + self.kuu * beta)
			  % As described in page 385 of concepts and applications of finite element analysis. 
			  
			The dynamic solver is the solve\_dynamic\_harmonic method within the BeamSystem class. This method solves for the global and local amplitude for each beam. The local displacements for each beam object within the beam system are solved by running the solve\_local method within each Beam object. The solve\_shape\_functions\_dynamic method and find\_stresses\_dynamic methods are used to find the state of stress at stable equilibrium within each beam. 
			
		\subsection{Transient} \label{ss:transient}
			
			The transient solver finds the reactions, displacements, and rotations over time given a user defined time-varying force and moment. The inputs are a timestep interval (${\delta}T$), the timestep count ($T_n$), and $\alpha$ and $\delta$ as constants for Newmark integrastion. Each force added to the system is described as a function of time. The newmark integration method is used to estimate the displacement, rotations, and reactions at each timestep. There is a constant duraiton between each timestep which is determined by the timestep interval. The stresses are calcaulated for each timestep. 
			
			The transient solver is initiated with the initialize_dynamic_transient method within the BeamSystem class. The solve_dynamic_transient method within the BeamSystem class solves for the global and local reactions, displacements, and rotations for each timestep. Within the BeamElement class, the solve_shape_functions_transient and find_stresses_transient methods are used to find the stresses and strains for each beam at each timestep.

If set to a number the design variable is fixed and is not analyzed by the optimizer. This is done after it is determined that the boundary condition is the active constraint so the design variable does not need to be considered. Fixing the design variables saves on computation time.

The function outputs the resulting design variables as well as the result of thee objective function.
